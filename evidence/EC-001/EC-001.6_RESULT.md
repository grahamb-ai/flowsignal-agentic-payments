# EC-001.6 — Non-Formation

## Challenge
Demonstrate that when execution is refused or blocked, the prohibited represented consequence does not form.

## Classification
**PASS — REPRESENTED HARNESS NON-FORMATION**

**ND — EXTERNAL PHYSICAL NON-FORMATION**

## Evidence
The public harness explicitly represents consequence state through values including:

- `EXECUTION PERMITTED`
- `EXECUTION WITHHELD`
- `NO EXECUTION`

Focused EC-001.6 tests confirm that:

1. AP-003 — changed state → Runtime Authority `REFUSE` → Execution Gateway `BLOCKED` → `NO EXECUTION`
2. AP-005 — expired mandate → Runtime Authority `REFUSE` → Execution Gateway `BLOCKED` → `NO EXECUTION`
3. AP-006 — substituted action → Execution Gateway `BLOCKED` / `ACTION_BINDING_MISMATCH` → `NO EXECUTION`

These tests are implemented in:

`harness/tests/test_ec001_6_non_formation.py`

## Relationship to earlier evidence
The earlier FS-CT evidence already recorded that external consequence non-formation is not demonstrable from the current public harness because it does not contain an independently consequence-producing banking or payment executor.

That limitation is preserved. The EC-001.6 result therefore distinguishes two claims:

### Demonstrated
Within the represented public FlowSignal Agentic Payments Harness execution surface, REFUSE/BLOCKED outcomes do not transition to the represented consequence state.

### Not demonstrated
The harness does not prove that every external banking rail, integration, privileged operator, datastore path, cloud control plane, administrative path, or other unrepresented executor is physically incapable of producing the prohibited consequence.

## Final result
**PASS — represented harness non-formation**

**ND — universal/external physical non-formation**

## Claim boundary
This result applies only to the public harness and the execution surfaces exercised by the tests. It must not be represented as proof of real-world payment settlement non-formation outside those surfaces.
