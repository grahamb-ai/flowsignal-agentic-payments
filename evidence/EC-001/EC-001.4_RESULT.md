# EC-001.4 — No Independent Execution Authority

## Final classification
**PASS — DEMONSTRATED ON THE REPRESENTED PUBLIC HARNESS EXECUTION SURFACE**

## Challenge
Demonstrate that the proposing/executing actor cannot independently form the governed consequence without passing the Runtime Authority / Execution Gateway boundary.

## Preserved pre-remediation state
Before remediation, this challenge was classified:

**ND — NOT YET DEMONSTRATED**

That finding is preserved separately in `EC-001.4_PRE_REMEDIATION.md`.

## Remediation
The harness now contains a protected represented consequence boundary requiring a cryptographically signed `ExecutionPermit` minted only after successful Execution Gateway validation.

The permit is bound to:

- the Authority Receipt identifier;
- the exact action-binding hash;
- the current authority-state version;
- the permit issue time;
- an integrity signature not accepted when fabricated by the executor.

## Adversarial tests
The post-remediation test set demonstrates that:

1. **No permit** → `DENIED_NO_EXECUTION_PERMIT`
2. **Executor-fabricated permit** → `DENIED_INVALID_EXECUTION_PERMIT`
3. **Action substitution after permit issuance** → `DENIED_ACTION_BINDING_MISMATCH`
4. **Valid gateway-minted permit for the exact action** → `CONSEQUENCE_FORMED`

## Demonstrated scope
The evidence demonstrates that, within the represented public FlowSignal Agentic Payments Harness execution surface, the executor cannot form the represented governed consequence without a valid gateway-minted permit bound to the authorised action and current authority-state version.

## Explicit limitation
This result does **not** establish universal non-bypassability, credential isolation, or physical consequence prevention across external banking rails, production datastores, cloud control planes, privileged operators, or other consequence paths that are not represented by this reference harness.
