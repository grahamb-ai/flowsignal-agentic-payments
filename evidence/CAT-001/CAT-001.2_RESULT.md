# CAT-001.2 — No Stale Authority

**Qualification date:** 20 August 2026  
**Target:** `Kamanaka5502/bind-time-authority-proof` public bounded demonstrator  
**Frozen target commit:** `d71d743e23098fb58454d8d412cb4a988681d2c1`  
**Classification:** PARTIAL — stale authority is rejected by the published decision simulation; represented consequence non-formation is NOT DEMONSTRATED

## Frozen proposition

> A previously valid authorization / standing object MUST NOT continue to authorize a represented consequence after a material authority-state change that makes it stale.

## Target's own public claim

The frozen README states that the demonstrator may show stale-authority refusal and defines invariant I1 as authority mismatch at commit forcing `REFUSE`. The formal specification states that current epoch-valid authority is required at bind time and that permission prior to the bind boundary is non-binding.

## Published artifacts inspected

- `bind_time_authority_fabric/advanced_execution_field.py`
- `bind_time_authority_fabric/authority_epoch.py`
- `bind_time_authority_fabric/invariants.py`
- `bind_time_authority_fabric/standing_token.py`
- `README.md`
- `FORMAL_SPEC.md`

## Mechanism observed

The published simulation constructs authority at epoch 1 and a standing token at epoch 1. The token remains the historical object. At step 4 the simulation revokes authority and increments the current authority epoch.

The historical token's signature remains valid, but its epoch no longer equals the current authority epoch. The decision expression therefore returns `REFUSE`, because `EXECUTE` requires both current authority validity and equality between token epoch and authority epoch.

This is useful evidence because it distinguishes cryptographic validity from current standing: a historically signed object can remain signature-valid while becoming stale relative to authority state.

`invariants.py` additionally asserts that an `EXECUTE` decision requires token epoch to equal authority epoch and that invalid authority cannot produce `EXECUTE` on that simulation path.

## Initial result

The public simulation supports the narrow proposition that a previously valid standing object does not continue to produce an `EXECUTE` decision after represented authority revocation / epoch change.

However, the frozen CAT-001.2 proposition requires more than a decision string: the stale object must not continue to authorize a **represented consequence**.

The inspected stale-authority simulation does not expose a distinct protected consequence-producing operation whose non-formation can be observed after the stale object is presented. The hash-chain payload appended during the simulation is not a protected consequence whose absence proves refusal enforcement.

The repository contains a separate HTTP `/commit` surface, but the frozen public evidence does not compose that route with the stale-token / authority-epoch-change mechanism into one reproducible stale-object test.

## Classification

**PARTIAL — stale authority rejection is demonstrated at the published decision-simulation layer; represented consequence non-formation is NOT DEMONSTRATED by this proposition.**

## Demonstrated scope

On the frozen public simulation surface:

> A standing object created under authority epoch 1 remains cryptographically verifiable after the represented authority changes, but is no longer accepted for `EXECUTE` once current authority is invalid / epoch-mismatched.

## Residual limitations

This result does not demonstrate:

- end-to-end prevention of a represented protected consequence after stale-authority refusal;
- closure of every public or external execution route;
- persistence or restart behavior for stale standing objects;
- distributed revocation propagation;
- production process / IAM / KMS / HSM isolation;
- external physical consequence non-formation;
- properties of the undisclosed production authority fabric.

## What this result does not prove

It would be claim inflation to translate this result into `stale authority can never execute` without retaining the bounded simulation scope.

The evidence supports:

> `stale standing is rejected by the published decision simulation`.

It does not yet support:

> `a stale standing object cannot form the represented protected consequence through the tested demonstrator boundary`.
