# CAT-001.2 — Refusal / Represented Consequence Non-Formation

**Qualification date:** 20 August 2026  
**Target:** `Kamanaka5502/bind-time-authority-proof` public bounded demonstrator  
**Frozen target commit:** `d71d743e23098fb58454d8d412cb4a988681d2c1`  
**Classification:** PARTIAL — refusal gates the published `/commit` chain-advance path; protected consequence non-formation is NOT DEMONSTRATED

## Frozen proposition

> When the authority determination is `REFUSE`, the represented protected consequence MUST NOT form.

## Target's public claim

The frozen README states:

- `Authority mismatch at commit forces REFUSE.`
- `If authority cannot be proven at the consequence boundary, execution does not proceed.`

The same README explicitly limits all runnable code to a bounded demonstrator and says the private corridor implementation, protected runtime law, production ledger and commercial deployment architecture are not disclosed.

## Published enforcement surface inspected

`boundary_server.py` exposes a `/commit` route. Within that route it:

1. validates an allowed corridor;
2. enforces the expected parent chain tip;
3. evaluates `DeterministicBoundary.evaluate(prior_tip)`;
4. if the resulting decision is not `EXECUTE`, returns HTTP 403 before incrementing `RECEIPT_INDEX`, updating `CHAIN_TIP`, appending a receipt, or persisting the ledger;
5. only the `EXECUTE` branch advances the published receipt/commit chain.

This is genuine gating of the represented chain-advance operation on the `/commit` path.

## Important testability limitation

On the frozen `boundary_server.py` implementation, `DeterministicBoundary.evaluate()` calls `simulate(steps=5)`. `compute_phi(history)` is `-1 + (len(history) * 0.2)`. With exactly five history elements this evaluates to `0.0`, therefore `authority_valid = phi >= 0` is always true for the normal published `/commit` evaluation.

Accordingly, the frozen public HTTP surface does not expose an input by which an external caller can cause the authority determination itself to become `REFUSE` through changed authority state. The refusal branch exists, but CAT-001.2 cannot independently exercise an authority-driven REFUSE on that route from the published interface alone.

The separate `advanced_execution_field.py` and `adversarial_execution_field.py` simulations do produce `REFUSE` after represented authority mutation, but they do not expose a separate protected consequence-producing operation whose absence can be observed after refusal.

## Result

Two distinct things are demonstrated:

1. **Published route gating:** on `/commit`, a non-`EXECUTE` result returns before the represented chain/receipt mutation. This supports a bounded enforcement mechanism on that single published route.
2. **Authority-change refusal:** separate simulations demonstrate changed authority producing `REFUSE`.

What is **not** demonstrated by the frozen public surface is the composition of those properties into one executable proof showing:

`authority changes -> REFUSE -> attempted protected consequence -> consequence does not form`.

Nor does the public repository demonstrate universal route closure or prevention of an external/physical consequence.

## Classification

**PARTIAL — refusal gates the published `/commit` chain-advance path; protected consequence non-formation is NOT DEMONSTRATED.**

This is not classified FAIL because the inspected route contains a real refusal-before-chain-mutation guard. It is not classified PASS because the authority-driven refusal cannot be exercised through the published `/commit` interface and the repository does not expose a separate consequence surface proving non-formation after that refusal.

## Strongest safe conclusion

> On the frozen public demonstrator, the `/commit` route is coded so that a non-`EXECUTE` decision returns before the represented receipt-chain mutation. However, the public interface does not expose an authority-state mutation capable of independently driving that route to `REFUSE`, and no separate protected consequence surface demonstrates non-formation. The full refusal-to-non-formation proposition therefore remains only partially demonstrated.

## Residual proof obligations

- executable authority-driven `REFUSE` through the consequence route;
- attempted consequence formation after that refusal;
- observable proof that represented consequence did not form;
- credible bypass/direct-consequence attempt;
- route closure beyond the single published `/commit` handler;
- external/physical consequence non-formation;
- production enforcement, which is outside the declared public repository boundary.
