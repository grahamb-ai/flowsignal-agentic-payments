# CAT-001.10 — Restart / Persistence

**Qualification date:** 20 August 2026  
**Target:** `Kamanaka5502/bind-time-authority-proof` public bounded demonstrator  
**Frozen target commit:** `d71d743e23098fb58454d8d412cb4a988681d2c1`  
**Classification:** PARTIAL — receipt-chain state is persisted/reloaded; security-relevant authority state across restart is NOT DEMONSTRATED

## Frozen proposition

> Where the public claim depends on state surviving process lifetime, security-relevant state MUST survive the represented restart boundary or the limitation must be explicit.

## Public persistence mechanism inspected

`boundary_server.py` persists `RECEIPT_LOG` to `receipt_ledger.json`. On startup, `load_ledger()` reloads that file and reconstructs `CHAIN_TIP` and `RECEIPT_INDEX` from the final stored receipt.

This is a real persistence mechanism for the represented receipt chain and is credited as such.

The server's deterministic evaluator, however, reconstructs its decision state afresh from a fixed deterministic simulation. It does not load the revocable authority/epoch state used by the separate `advanced_execution_field.py` / authority-state demonstrations.

## Restart assessment

The frozen CAT proposition specifically asks whether security-relevant state needed to prevent stale authority, replay, or resurrection survives a fresh process/documented restart boundary.

The public server demonstrates persistence of receipt-chain history, but CAT-001 does not find a published restart sequence preserving and rechecking the changed/revoked authority state used by the authority demonstrations.

Accordingly, the public surface does not establish that a pre-restart stale authority object remains stale because the relevant authority state itself survived restart. Nor does it demonstrate consumption/replay state across restart for a separately protected execution capability.

## Classification

**PARTIAL — receipt-chain state is persisted/reloaded; security-relevant authority state across restart is NOT DEMONSTRATED.**

This is not ND because the public demonstrator does make and implement a concrete persistence claim for its receipt ledger.

It is not PASS because the security-relevant authority state at issue in CAT-001 is not shown crossing the restart boundary with a stale-authority/replay consequence test.

It is not FAIL because CAT-001 has not demonstrated a protected consequence forming after restart from authority that should have remained invalid.

## Strongest safe conclusion

> The frozen public `/commit` server persists and reloads its represented receipt-chain state. The public proof surface does not demonstrate persistence of revocation/authority state or execution-capability consumption across restart. Restart/persistence is therefore PARTIAL for the CAT-001 authority proposition.

## Scope limitation

This does not assess undisclosed production databases, production authority stores, distributed persistence, crash recovery, or external ledgers.
