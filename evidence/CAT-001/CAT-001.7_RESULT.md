# CAT-001.7 — Refusal / Represented Non-Formation

**Qualification date:** 20 August 2026  
**Target:** `Kamanaka5502/bind-time-authority-proof` public bounded demonstrator  
**Frozen target commit:** `d71d743e23098fb58454d8d412cb4a988681d2c1`  
**Classification:** PARTIAL — refusal-before-route-mutation is implemented; authority-driven represented non-formation is NOT DEMONSTRATED end-to-end

## Frozen proposition

> When the runtime authority result is `REFUSE`, the represented protected consequence MUST NOT form.

## Required evidence

A PASS requires an executable lineage on the frozen public surface showing:

`authority/standing condition -> REFUSE -> attempted protected consequence -> observable non-formation`

A refusal string or decision object alone is insufficient. A consequence-like mutation must be identifiable and its absence after refusal observable.

## Public evidence inspected

The frozen public demonstrator contains two relevant but separate mechanisms.

### Authority-driven refusal

`bind_time_authority_fabric/advanced_execution_field.py` represents authority beginning valid, then becoming invalid with an advanced epoch. Its later decision requires current authority validity and token/current-epoch equality for `EXECUTE`; after revocation it selects `REFUSE`.

`adversarial_execution_field.py` similarly represents a changed authority condition and later `REFUSE` decisions.

These files therefore demonstrate decision-level refusal after represented authority change.

### Represented route mutation

`boundary_server.py` exposes `/commit`. Within that handler a non-`EXECUTE` decision returns HTTP 403 before the handler increments `RECEIPT_INDEX`, changes `CHAIN_TIP`, appends the receipt, or persists the ledger. This is a real refusal-before-mutation guard on that published route.

However, the frozen `/commit` evaluator uses its own deterministic state construction. The published interface does not expose the authority-state mutation used by the separate simulations as an input to this consequence-like route. Therefore CAT-001 cannot drive the documented `/commit` route through the same changed-authority sequence and observe the represented mutation remaining absent.

## Result

The target demonstrates both ingredients separately:

1. represented changed authority can produce `REFUSE` in the simulation surface; and
2. the `/commit` handler is coded to return before its represented chain mutation when its local decision is non-`EXECUTE`.

The frozen public surface does not demonstrate their composition into the full proposition:

`changed authority -> REFUSE -> attempted represented consequence -> no consequence formed`.

## Classification

**PARTIAL — refusal-before-route-mutation is implemented; authority-driven represented non-formation is NOT DEMONSTRATED end-to-end.**

This is not a FAIL because no represented consequence has been shown forming after a valid `REFUSE` on the governed public route.

It is not a PASS because the required authority-driven refusal cannot be exercised through the same published consequence route, so non-formation after that refusal is not independently observable.

## Strongest safe conclusion

> On the frozen public demonstrator, changed authority produces `REFUSE` on the simulation surface, and the separate `/commit` route contains code that returns before its represented receipt-chain mutation on a non-`EXECUTE` result. The public evidence does not join those mechanisms into one executable refusal-to-non-formation proof. Represented non-formation after authority-driven refusal is therefore only partially demonstrated.

## Scope limitation

No conclusion is drawn about external or physical consequence non-formation, production route closure, or undisclosed production enforcement. Those remain outside the declared public repository boundary.
