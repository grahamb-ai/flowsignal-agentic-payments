# CAT-001.8 — Deterministic Replay

**Qualification date:** 20 August 2026  
**Target:** `Kamanaka5502/bind-time-authority-proof` public bounded demonstrator  
**Frozen target commit:** `d71d743e23098fb58454d8d412cb4a988681d2c1`  
**Classification:** PARTIAL — deterministic simulation/chain comparison is represented; the full frozen authority replay matrix is NOT DEMONSTRATED

## Frozen proposition

> The demonstrator's replay claim MUST be reproducible for the state it says is deterministic.

CAT-001.8 requires at minimum:

1. same relevant state + same relevant inputs;
2. changed relevant state + historical authority / prior input;
3. replay after refusal, revocation, expiry, or supersession where such behavior is claimed.

## Public replay mechanisms inspected

`adversarial_replay_harness.py` calls `simulate()`, deep-copies the returned chain, mutates the final chain item by appending `_tampered`, and reports whether the original and mutated chains differ.

The package `bind_time_authority_fabric/advanced_execution_field.py` builds a deterministic-looking simulation from fixed initial values, revokes its local authority at step 4, appends hashes of the simulated state to a `CommitChain`, and returns that hash list.

The repository also contains `ci_replay_check.py`, which is intended to call a simulation twice and compare the resulting chains, then compare Merkle roots and run signature/latency checks.

## Evidence supported

The public design therefore contains genuine replay-oriented mechanisms:

- fixed-state simulation;
- repeat-chain comparison intent;
- deterministic hashing/canonicalization helpers;
- mutation/tamper comparison;
- represented revocation within the simulation history.

These support a bounded deterministic-evidence concept.

## Limitations against the frozen proposition

The frozen CAT proposition is stronger than simply observing that two deterministic simulations can produce matching hash lists or that a manually altered list differs.

The inspected public replay harness does not itself preserve and re-submit a historical authority object against a separately changed current authority state and consequence boundary. Nor does it expose a replay sequence after refusal/revocation in which the same protected action is re-attempted and the resulting consequence state is observed.

Additionally, the frozen root-level `adversarial_replay_harness.py` imports `advanced_execution_field` as a root-level module, while the inspected implementation is present under `bind_time_authority_fabric/advanced_execution_field.py`. That import/run-layout issue is relevant to CAT-001.15 independent reproduction and is not converted here into a replay-semantics FAIL.

## Classification

**PARTIAL — deterministic simulation/chain comparison is represented; the full frozen authority replay matrix is NOT DEMONSTRATED.**

This is not a FAIL because the public repository contains meaningful deterministic/replay mechanisms and mutation comparison.

It is not a PASS because CAT-001.8 requires replay under unchanged and changed authority state, including historical authority after revocation/refusal where claimed, tied to the represented protected action. That full matrix is not demonstrated by the inspected public replay surface.

## Strongest safe conclusion

> The frozen public demonstrator contains deterministic simulation, hashing and chain-comparison mechanisms and can represent changed authority within a generated history. It does not demonstrate the complete CAT-001 replay burden of reusing historical authority against changed current state and observing the protected consequence outcome. Deterministic replay is therefore PARTIAL within the public proof surface.

## Scope limitation

This result does not assess undisclosed production replay, durable restart replay, distributed replay, or production ledger semantics.
