# CAT-001.12 — Durable State Rollback

**Qualification date:** 20 August 2026  
**Target:** `Kamanaka5502/bind-time-authority-proof` public bounded demonstrator  
**Frozen target commit:** `d71d743e23098fb58454d8d412cb4a988681d2c1`  
**Classification:** PARTIAL — a durable receipt-ledger surface exists, but rollback-resistant authority/execution state is NOT DEMONSTRATED

## Frozen proposition

> If the public demonstrator relies on durable authority / execution state, restoration of older durable state MUST NOT silently resurrect authority or execution capability that the demonstrator claims is no longer valid.

## Public durable surface

`boundary_server.py` persists `RECEIPT_LOG` as `receipt_ledger.json` and reconstructs `CHAIN_TIP` and `RECEIPT_INDEX` from that file at startup.

This provides a concrete durable surface to which the rollback proposition is relevant.

The separate authority-revocation demonstrations, however, do not persist their authority epoch / validity state into that ledger or another inspected durable authority store.

## Rollback assessment

The JSON ledger is the server's source for restoring receipt-chain state. The frozen public surface does not expose an independent monotonic anchor, durable generation counter, external checkpoint or other surviving reference against which restoration of an older otherwise internally coherent ledger can be rejected.

The replay function reconstructs expected commitments from the receipts currently present. That can detect inconsistency within the loaded chain, but the inspected public mechanism does not by itself establish that an older coherent snapshot is stale relative to a newer state that has been lost/restored away.

CAT-001 does not convert that architectural observation into a FAIL because no authorized rollback experiment has been executed against the target repository and the authority-state mechanism is not durably composed with the server surface.

## Classification

**PARTIAL — a durable receipt-ledger surface exists, but rollback-resistant authority/execution state is NOT DEMONSTRATED.**

This is not ND because the public server does rely on durable ledger state.

It is not PASS because the public evidence does not demonstrate rejection of an older coherent durable snapshot or preservation of a monotonic authority/execution reference across rollback.

It is not FAIL because CAT-001 has not demonstrated a previously invalid/consumed protected action successfully forming a second represented consequence after an executed rollback challenge.

## Strongest safe conclusion

> The frozen public server persists a receipt chain, but the published proof surface does not demonstrate a surviving monotonic reference capable of distinguishing the latest durable state from an older internally coherent restored snapshot. Durable rollback resistance is therefore only PARTIAL within CAT-001.

## Scope limitation

No conclusion is drawn about undisclosed production ledgers, external anchors, immutable storage, backup controls, production authority stores or disaster-recovery architecture.
