# CAT-001.6 — Independent Execution Capability

**Qualification date:** 20 August 2026  
**Target:** `Kamanaka5502/bind-time-authority-proof` public bounded demonstrator  
**Frozen target commit:** `d71d743e23098fb58454d8d412cb4a988681d2c1`  
**Classification:** NOT DEMONSTRATED (ND) — no separately issued execution capability or isolated executor is exposed by the frozen public demonstrator

## Frozen proposition

> Within the represented boundary, code or components outside the authority decision / issuance mechanism MUST NOT be able to manufacture or independently obtain whatever execution capability is sufficient to form the protected consequence.

## Required evidence

CAT-001 requires an attempt to create, forge, substitute, or directly invoke the execution-enabling capability using only the accessible public demonstrator surface.

Module-level or same-process separation must not be described as production IAM / KMS / HSM or process-isolation proof unless those boundaries are actually demonstrated.

## Public surface inspected

The frozen public demonstrator exposes several authority-related mechanisms, including:

- `bind_time_authority_fabric/standing_token.py`, which creates and verifies HMAC-signed public demonstrator standing tokens;
- `bind_time_authority_fabric/advanced_execution_field.py`, which evaluates a simulated `EXECUTE` / `REFUSE` decision using authority validity, signature validity and epoch equality;
- `boundary_server.py`, whose `/commit` handler performs its decision and represented receipt-chain mutation in the same server module and request path.

The README expressly states that the public key mechanism is not production key management and that production authority evaluator, key-management architecture, private signing infrastructure, private standing-token format, private corridor implementation and commercial deployment architecture are outside the public proof surface.

## Capability-boundary assessment

On the frozen public surface, CAT-001 does not identify a distinct execution capability issued by one component and required by a separately isolated consequence executor.

The standing token is an authority/standing object used by the simulation, but the public `/commit` handler does not require presentation of that standing token or another separately issued execution permit before advancing its represented receipt chain. Its decision and mutation are co-located.

Accordingly, there is no public capability boundary on which CAT-001 can perform the frozen create/forge/substitute/direct-invocation challenge and then observe whether a protected consequence is admitted or rejected.

The public demonstrator key source in `standing_token.py` is intentionally available to the demonstrator, including a documented default demo key when the environment variable is absent. That is not treated as a production key-isolation failure because the repository explicitly says this is not production key management. It also cannot establish independent execution-capability isolation.

## Result

**NOT DEMONSTRATED (ND).**

The frozen public repository does not expose the architecture required to prove or falsify CAT-001.6: a separately identifiable execution capability plus a protected executor that requires that capability and cannot independently manufacture it.

This is not a FAIL. CAT-001 has not demonstrated that an unauthorized component can form the target's protected production consequence, and the target explicitly withholds its production signing and execution architecture.

It is not a PASS because no independently testable public capability-isolation boundary is present.

## Strongest safe conclusion

> The frozen public demonstrator exposes authority-token and decision mechanisms, but it does not expose a separately issued execution capability bound to an isolated protected executor. Therefore independent execution-capability isolation is NOT DEMONSTRATED by the public proof surface. No conclusion is drawn about the undisclosed production architecture.

## Residual proof obligations

- identify a public execution-enabling capability distinct from the authority evaluator;
- identify the executor/consequence boundary that requires it;
- demonstrate that the executor cannot manufacture or obtain the capability independently;
- attempt capability forgery/substitution/direct invocation on that published boundary;
- preserve the resulting consequence outcome;
- production process, IAM, KMS/HSM and signing-custody isolation remain outside the declared public repository boundary.
