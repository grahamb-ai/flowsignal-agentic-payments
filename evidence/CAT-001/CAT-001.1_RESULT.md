# CAT-001.1 — Standing at Effect

**Qualification commenced:** 20 August 2026  
**Target frozen:** 20 August 2026  
**Target repository:** `Kamanaka5502/bind-time-authority-proof`  
**Frozen target commit:** `d71d743e23098fb58454d8d412cb4a988681d2c1`  
**Classification:** **PARTIAL**

## Frozen proposition

Authority relied upon for consequence formation MUST be evaluated against the authority state that stands at the represented consequence boundary, rather than relying solely on historical request-time or approval-time state.

## Target's own public claim

The frozen README states that standing must be evaluated at the moment consequence would bind and that if standing cannot be proven at that boundary execution must refuse. `FORMAL_SPEC.md` similarly says execution is admitted iff standing holds at the bind-time commit boundary and that prior permission is non-binding.

## Public artifacts examined

- `README.md`
- `FORMAL_SPEC.md`
- `bind_time_authority_fabric/advanced_execution_field.py`
- `bind_time_authority_fabric/invariants.py`
- `bind_time_authority_fabric/authority_epoch.py`
- `boundary_server.py`

All observations are limited to the frozen public revision. No conclusion is drawn about any undisclosed production implementation.

## Published mechanism

The modular `advanced_execution_field.py` initializes authority as valid at epoch 1 with a standing token associated with epoch 1. At simulation step 4 it invalidates authority and increments the authority epoch. The subsequent decision expression uses the current `authority.valid` value and equality between the token epoch and current authority epoch. The associated invariant requires `REFUSE` when authority is invalid.

This supports the narrow proposition that the modular simulation recalculates its decision using changed authority state rather than relying solely on the earlier-valid state.

## Evidence limitation

The modular simulation does not expose a separate protected consequence object or consequence-formation operation whose state can be observed before and after the determination. Its hash-chain append occurs for simulation payloads irrespective of whether the decision is `EXECUTE` or `REFUSE`; that append therefore cannot, without additional evidence, be treated as the protected consequence whose formation CAT-001.1 requires us to observe.

`boundary_server.py` exposes an HTTP `/commit` path and does not advance its receipt chain when its own deterministic evaluator returns a non-EXECUTE decision. But in the frozen file that evaluator derives `authority_valid` from `phi >= 0`; it does not expose the earlier-valid → authority-change → bind-time standing transition required to connect that server path to CAT-001.1.

The public surfaces therefore show complementary pieces — changed authority affecting a decision in the modular simulation, and a commit-like server path — but the frozen public evidence examined does not establish them as one observable end-to-end consequence-formation test.

## Initial result

The public demonstrator supports the architectural proposition that current authority state is consulted after an earlier state can change, and its represented decision changes to `REFUSE` after revocation.

It does **not**, on the public evidence examined for this result, establish the full CAT-001.1 PASS condition: an observable represented protected consequence that forms only when the authority relied upon still has standing at that tested boundary.

## Earned classification

**PARTIAL**

### Demonstrated scope

Within the frozen modular public simulation, authority is changed after initial validity and subsequent decision logic consults the changed authority/epoch state rather than relying solely on the earlier-valid state.

### Residual limitation

Observable end-to-end coupling between that changed authority determination and formation/non-formation of a distinct represented protected consequence is not demonstrated by the artifacts examined for CAT-001.1.

## What this result does not prove

This result does not prove that the target's private or production architecture lacks a protected consequence boundary. It does not prove a bypass. It does not establish production route closure, production key isolation, distributed atomicity, or physical consequence non-formation.

It records only what the frozen public proof surface has earned against CAT-001.1.
