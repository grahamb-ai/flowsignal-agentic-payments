# CAT-001.3 — Credible Bypass / Route Closure

**Qualification date:** 20 August 2026  
**Target:** `Kamanaka5502/bind-time-authority-proof` public bounded demonstrator  
**Frozen target commit:** `d71d743e23098fb58454d8d412cb4a988681d2c1`  
**Classification:** PARTIAL — governed `/commit` route contains inline gating; route closure / non-bypassability is NOT DEMONSTRATED

## Frozen proposition

> A represented protected consequence MUST NOT be reachable through a credible public demonstrator path that bypasses the authority determination intended to protect it.

## Public claims relevant to the proposition

The frozen README states that if authority cannot be proven at the consequence boundary, execution does not proceed. The frozen threat model describes an `Admission gate before execution`, `Corridor isolation`, an `Immutable authority root`, and a `Sovereign execution guard`, and states `No partial bind` and mandatory fail-closed semantics.

The README simultaneously declares the repository a bounded demonstrator and explicitly withholds the private corridor implementation, protected runtime law, production ledger and commercial deployment architecture.

## Public surface inspected

The frozen repository tree was reviewed for public consequence/execution surfaces. The principal HTTP execution surface found is `boundary_server.py`.

On `/commit`, the authority decision and the represented receipt-chain mutation are located in the same handler and protected by the same process lock. The handler performs corridor and parent checks, evaluates `DeterministicBoundary.evaluate(prior_tip)`, returns before chain mutation if the decision is not `EXECUTE`, and only then updates `RECEIPT_INDEX`, `CHAIN_TIP`, appends the receipt and persists the ledger.

This is meaningful route-local gating.

## Credible bypass assessment

The public repository does not expose a separate public consequence API, executor, payment rail, mutation endpoint or protected resource whose only capability to mutate is issued by the authority evaluator. Consequently, there is no independently exposed consequence surface against which CAT-001.3 can attempt a direct invocation while omitting the authority determination.

The represented consequence in `boundary_server.py` is the same module's mutation of module-global receipt-chain state and a JSON ledger file. The evaluator and mutation code are co-located. The code does not expose a distinct execution capability, permit, token or authority-bound command that must be presented to a separately isolated executor.

That means the public demonstrator supports the narrower statement:

> Requests using the documented `/commit` handler traverse the inline decision gate before that handler advances its represented receipt chain.

It does **not** provide evidence for the stronger statement:

> All credible paths to the represented or external consequence are closed unless the authority gate permits execution.

No attempt has been made to modify, instrument, bypass access controls on, or republish the target implementation. This result is based solely on the frozen public files and documented/public surfaces.

## Result

**PARTIAL — governed `/commit` route contains inline gating; route closure / non-bypassability is NOT DEMONSTRATED.**

This is not a FAIL. A bypass has not been demonstrated. The public proof surface simply does not expose the independent consequence boundary required to falsify or prove the stronger non-bypassability proposition.

It is not a PASS because observing that one route contains a gate is not evidence that every credible route to the consequence is closed.

## Strongest safe conclusion

> On the frozen public demonstrator, the documented `/commit` handler places its represented receipt-chain mutation after an inline authority decision and returns before that mutation on a non-`EXECUTE` result. CAT-001.3 found no separately exposed public consequence surface on which to execute a direct bypass challenge. Therefore governed-route gating is demonstrated, while route closure and non-bypassability remain NOT DEMONSTRATED.

## Residual proof obligations

- identify a separately observable represented protected consequence;
- show that the consequence cannot be invoked directly without an authority result/capability;
- demonstrate failed direct invocation/bypass attempt;
- demonstrate no alternate public mutation path reaches the same consequence;
- demonstrate execution capability separation if claimed;
- production route closure, process/IAM/key isolation and external physical consequence protection remain outside the declared public repository boundary.
