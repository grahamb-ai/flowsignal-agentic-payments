# PMQ-002.9 — Two-Store Atomicity Crash Result

## Frozen proposition

> Durable permit consumption and creation of the initial represented consequence-outcome state MUST NOT be separable by a crash window that leaves the permit consumed with no recoverable execution outcome.

## Lineage

### 1. Frozen challenge

The PMQ-002.9 challenge deliberately terminates the executor after the permit-consumption transaction has committed but before the first consequence-outcome-store write can commit.

### 3. Initial remediation and regression

The reference persistence mechanism was changed so permit consumption and creation of `CONSEQUENCE_OUTCOME_UNRESOLVED` use one SQLite transaction spanning the local attached permit and outcome databases.

That first remediation exposed a regression in the previously qualified PMQ-002.2 two-process concurrency case. GitHub Actions run `32165194985` completed with:

**1 failed, 51 passed**

The failure was `sqlite3.OperationalError: database is locked` during concurrent attached-outcome-database initialization. PMQ-002.9 was therefore not treated as remediated merely because its local atomicity mechanism had changed: the existing concurrency property also had to remain intact.

### 4. Concurrency-preserving remediation

The attached-database atomic operation was strengthened with bounded SQLite busy/lock retry around the complete attempt using a fresh connection for each retry. This preserves the atomic permit-consumption + initial-outcome transaction while avoiding reuse of partially completed ATTACH/PRAGMA setup during a concurrent initialization race.

## Demonstrated scope

Within the represented reference-MVP local SQLite boundary exercised by PMQ-002.9:

- permit consumption and creation of the initial `CONSEQUENCE_OUTCOME_UNRESOLVED` execution state are committed in one attached-database transaction;
- the frozen crash challenge no longer leaves a consumed permit without a recoverable initial execution outcome;
- the consumed permit remains replay-protected; and
- the previously qualified represented two-process shared-store replay property remains green in the full regression suite.

## Residual limitations / NOT DEMONSTRATED

PMQ-002.9 does **not** demonstrate:

- production distributed transactions;
- database HA/failover/replication;
- atomicity across separate database servers, hosts or regions;
- distributed consensus or serializability beyond the represented SQLite mechanism;
- filesystem/fsync/power-loss guarantees;
- storage-loss or snapshot-rollback recovery;
- external payment-rail reconciliation or idempotency;
- external exactly-once execution;
- immutable/write-once audit;

This PASS is therefore a bounded reference-MVP persistence result, not a production distributed-systems certification.
