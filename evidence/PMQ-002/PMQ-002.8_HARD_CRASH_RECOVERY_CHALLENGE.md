# PMQ-002.8 — Hard Crash After Permit Consumption Challenge

## Frozen proposition

> If an executor process terminates after a valid execution permit has been durably consumed but before the represented consequence outcome has been durably recorded, recovery MUST NOT infer that the consequence formed; the durable state MUST expose the execution as unresolved rather than silently collapsing it into ordinary permit replay denial.

## Attack

1. Issue a valid execution permit for the current authority state and exact action binding.
2. Execute in a child process using durable permit-consumption and consequence-outcome stores shared with the recovery process.
3. Allow durable permit consumption to complete.
4. Terminate the child process immediately before represented consequence outcome recording, without allowing application exception handling to run.
5. Restart/recover against the same durable stores.
6. Determine whether recovery can distinguish:
   - permit consumed + consequence formed;
   - permit consumed + consequence explicitly not formed; and
   - permit consumed + outcome unresolved because the executor died inside the crash window.

## Failure condition

The proposition fails if the durable record contains only permit consumption and the recovery surface has no explicit unresolved state for the execution.

A subsequent `DENIED_EXECUTION_PERMIT_REPLAY` is not sufficient recovery evidence. It proves only that the permit was consumed; it does not prove whether the consequence formed before termination.

## Evidence discipline

This proposition is frozen before observing/remediating the current architecture. A hard process termination must bypass normal exception handling so PMQ-002.7 remediation cannot manufacture a `CONSEQUENCE_NOT_FORMED` record after the injected failure.

If the current architecture cannot expose the unresolved crash state, preserve the failure before changing implementation.

## Claim boundary

This is a represented reference-MVP process-crash/recovery challenge. It does not establish production host or power-loss durability, filesystem/fsync guarantees, distributed transactions, database HA, cross-node recovery, external payment-rail reconciliation, external exactly-once execution, universal route closure or physical consequence status.
