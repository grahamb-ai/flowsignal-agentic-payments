# PMQ-002.6 — Consequence Formed / Evidence Write Failure Result

## Frozen proposition

> If the represented protected consequence has formed, the system MUST retain a recoverable durable record of that formation even if the subsequent consequence-receipt creation path fails.

## Initial result

GitHub Actions run `32162230269`:

**1 failed / 48 passed**

Classification:

**FAIL — CONSEQUENCE FORMED WITHOUT RECOVERABLE OUTCOME EVIDENCE**

The represented protected consequence could return `CONSEQUENCE_FORMED`, after which injected receipt creation failure left no durable recoverable consequence-outcome record.

The failure was preserved in `PMQ-002.6_INITIAL_FAILURE.md` before remediation.

## Remediation

A durable reference consequence-outcome store was added. Before the executor returns `CONSEQUENCE_FORMED`, it now persists a record keyed by the execution permit signature and bound to the action-binding hash and outcome.

If that durable write fails, the represented executor raises instead of claiming `CONSEQUENCE_FORMED`. The subsequent `ConsequenceOutcomeReceipt` remains a separate evidence object; failure to create it no longer erases the recoverable fact that represented formation occurred.

The frozen test remained unchanged: receipt creation is still deliberately failed immediately after represented formation and the test then queries the durable outcome store.

## Final classification

**PASS — represented consequence formation remains recoverable after injected receipt-creation failure**

## Demonstrated scope

Within the represented reference-MVP execution path, `CONSEQUENCE_FORMED` is no longer returned before a durable recoverable outcome record exists.

## Residual limitations / NOT DEMONSTRATED

This does **not** demonstrate:

- external payment or settlement evidence;
- production database high availability or replication;
- power-loss/fsync guarantees beyond the represented SQLite mechanism;
- distributed transactions between authority, evidence and external consequence systems;
- immutable/write-once audit storage;
- external exactly-once execution;
- recovery after storage corruption or infrastructure administrator compromise.

Those remain separate proof obligations.

## Strongest safe conclusion

Within the represented MVP boundary exercised by PMQ-002.6, an injected failure in consequence-receipt creation after represented consequence formation no longer leaves the system without recoverable evidence that the consequence formed.
