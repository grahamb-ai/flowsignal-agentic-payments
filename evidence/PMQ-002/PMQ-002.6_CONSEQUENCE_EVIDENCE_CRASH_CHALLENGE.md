# PMQ-002.6 — Consequence Formed / Evidence Write Failure Challenge

## Status

FROZEN BEFORE EXECUTION

## Purpose

Challenge the represented failure window in which a protected consequence forms but creation or persistence of the consequence evidence fails immediately afterwards.

## Frozen proposition

> If the represented protected consequence has formed, the system MUST retain a recoverable durable record of that formation even if the subsequent consequence-receipt creation path fails.

The proposition does not require the caller to receive a successful receipt when evidence creation fails. It requires the fact of represented consequence formation not to be lost or become unknowable to the reference system.

## Test method

1. Obtain a valid ALLOW decision and execution permit.
2. Configure isolated durable permit-consumption and consequence-outcome stores.
3. Execute the protected consequence through the receipt-producing path.
4. Inject a failure into consequence receipt creation immediately after consequence formation.
5. Confirm the call fails rather than falsely returning a successful receipt.
6. Query the represented durable consequence-outcome store.
7. Assert that a recoverable record exists proving the represented consequence formed and binding that fact to the execution permit/action.

## Failure condition

Classify **FAIL — CONSEQUENCE FORMED WITHOUT RECOVERABLE OUTCOME EVIDENCE** if consequence formation occurs, receipt creation fails, and the reference system has no durable recoverable record that the consequence formed.

## Claim boundary

This is a reference-MVP crash-window/evidence-durability challenge. A PASS would not establish external settlement evidence, database HA, write-ahead replication, exactly-once external execution, distributed transactions, power-loss durability, or production write-once audit guarantees.

The proposition and failure condition must not be weakened after observing the result.
