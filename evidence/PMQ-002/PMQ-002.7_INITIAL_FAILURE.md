# PMQ-002.7 — Initial Failure

## Frozen proposition

> If a valid execution permit has been durably consumed but the executor fails before the represented consequence forms, recovery MUST preserve an explicit recoverable state showing that the consequence did not form; the system MUST NOT silently collapse that state into an indistinguishable consumed-permit replay denial.

## Initial execution

GitHub Actions run: `32163123583`

Integrated result:

**1 failed / 49 passed**

## Classification

**FAIL — CONSUMED PERMIT LEFT WITHOUT RECOVERABLE NON-FORMATION OUTCOME**

## Observed failure

The execution permit was durably consumed. The injected executor failure then occurred before represented consequence formation. No consequence-outcome store existed for the attempt, so recovery could establish only that the permit had been consumed.

A later retry would be denied as replay, but that denial does not establish whether the earlier represented consequence formed.

## Scope

This failure is demonstrated for the reference harness's injected exception window after durable permit consumption and before represented consequence formation. It does not establish behavior under hard process termination, host power loss, storage loss or external payment-rail ambiguity.

The failure is preserved before remediation.
