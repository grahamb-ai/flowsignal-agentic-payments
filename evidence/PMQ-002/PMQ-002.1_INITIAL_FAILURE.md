**Qualification tranche:** PMQ-002 — Persistence, Concurrency and Failure-Boundary Qualification  
**Proposition:** A Runtime Authority execution permit that has already been consumed MUST NOT be capable of forming a second represented consequence after process restart.  
**Status:** INITIAL FAILURE PRESERVED  
**Date:** 2026-08-18

## Frozen test

The proposition and executable challenge were committed before observing the result. The test:

1. obtains a valid ALLOW-derived execution permit;
2. forms the represented protected consequence once;
3. simulates process-local replay-state loss by reloading the protected consequence component; and
4. presents the exact same previously consumed permit with the exact same action binding again.

The pass condition required the second attempt to be denied.

## Classification

**FAIL — RESTART REPLAY FORMS SECOND REPRESENTED CONSEQUENCE**

## Engineering finding

The pre-PMQ-002 replay control was process-local. It prevented sequential and concurrent duplicate use while the process-local consumed-permit registry remained intact, but that registry did not survive represented restart. The failure therefore confirms the previously declared residual limitation rather than contradicting the earlier bounded PMQ-001 claim.

## Scope

Demonstrated failure scope:

- represented FlowSignal Agentic Payments MVP execution surface;
- replay of the exact previously consumed execution permit;
- loss of module/process-local replay memory through component reload;
- same authority-state version and same action binding.

This result does **not** establish behaviour across real container or host restart, separate machines, external payment rails, distributed databases or production infrastructure.

## Evidence discipline

This failure is retained as part of the qualification lineage. Remediation MUST NOT weaken or replace the frozen proposition. The same semantic challenge must be rerun after any strengthening.
