# PMQ-002.8 — Hard Crash After Permit Consumption Result

## Frozen proposition

> If an executor process terminates after a valid execution permit has been durably consumed but before the represented consequence outcome has been durably recorded, recovery MUST NOT infer that the consequence formed; the durable state MUST expose the execution as unresolved rather than silently collapsing it into ordinary permit replay denial.

## Lineage

### 1. Frozen challenge

The proposition and hard-process-crash test were committed before runtime remediation. The test uses a spawned process and `os._exit(73)` after durable permit consumption and before represented consequence outcome recording, bypassing normal Python exception handling.

### 2. Initial fixture run

The first run did not reach the intended crash boundary because the spawned process began with fresh authority state and rejected the permit before consumption.

Classification:

**NOT EVALUATED — fixture authority-state mismatch prevented the frozen crash point from being reached.**

Only the fixture was corrected so the child process advanced to the permit's already-issued authority-state version. The proposition and crash semantics were unchanged.

The failure was preserved in `PMQ-002.8_INITIAL_FAILURE.md` before remediation.

### 4. Remediation

After successful durable permit consumption, the represented executor now persists:

`CONSEQUENCE_OUTCOME_UNRESOLVED`

before entering the remaining consequence-formation interval.

The state transition is therefore represented as:

`permit consumed -> CONSEQUENCE_OUTCOME_UNRESOLVED -> CONSEQUENCE_FORMED`

or, for a catchable represented pre-formation failure:

`permit consumed -> CONSEQUENCE_OUTCOME_UNRESOLVED -> CONSEQUENCE_NOT_FORMED`

If the executor process terminates abruptly after consumption and before either terminal outcome is recorded, the durable unresolved state remains available to recovery.

The frozen hard-crash test was not weakened or rewritten for the remediation.

## Final classification

**PASS — represented hard-process-crash window exposes durable unresolved consequence outcome after remediation**

## Demonstrated scope

Within the represented reference-MVP surface exercised by PMQ-002.8:

- permit consumption survives the tested abrupt child-process termination;
- the executor records an explicit unresolved outcome before the remaining formation interval;
- abrupt process termination at the frozen crash point leaves that unresolved state recoverable;
- recovery does not need to infer consequence formation from permit consumption alone; and
- the consumed permit remains unavailable for ordinary replay.

## Residual limitations / NOT DEMONSTRATED

PMQ-002.8 does **not** demonstrate:

- atomic commit across the separate permit-consumption and consequence-outcome stores;
- crash/power loss between permit-store commit and unresolved-outcome-store commit;
- filesystem or fsync durability guarantees;
- production database HA/failover;
- cross-host/container recovery;
- distributed transactions or consensus;
- multi-region recovery;
- external payment-rail reconciliation or idempotency;
- external exactly-once execution;
- universal route closure; or
- physical consequence status.

The remaining two-store atomicity gap is a separate proof obligation and must not be implied away by this PASS.
