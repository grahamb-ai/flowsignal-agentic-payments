# PMQ-002.5 — Authority-State Rollback / Stale-State Resurrection Challenge

## Status

FROZEN BEFORE EXECUTION

## Purpose

Challenge whether an authority state that has been superseded can later be restored and thereby make an execution permit bound to that old state appear current again.

## Frozen proposition

> Once authority state version N has been superseded by a later committed version, the represented authority-state mechanism MUST NOT permit the current state to move backwards to N such that an execution permit bound to N can regain standing and form the represented protected consequence.

## Test method

1. Obtain a valid ALLOW decision and execution permit bound to the current authority-state version N.
2. Commit a newer authority state N+1.
3. Confirm the permit bound to N is stale and cannot form the represented consequence.
4. Attempt to restore/rollback the represented authority state to N through the authority-store surface available to the harness.
5. If rollback is possible, present the original still-cryptographically-valid permit again.
6. Assert that the superseded state cannot be resurrected into current standing and that the old permit cannot regain authority to form the represented consequence.

## Failure condition

Classify **FAIL — SUPERSEDED AUTHORITY STATE RESURRECTED** if the represented authority store can move backwards to an already-superseded version and an old permit can consequently regain current standing and form the represented consequence.

## Claim boundary

This is a reference-harness authority-state monotonicity test. A PASS would not establish production database anti-rollback controls, immutable ledgers, distributed consensus, storage-level tamper resistance, external IAM state monotonicity, or recovery from malicious infrastructure administrators.

The proposition and failure condition must not be weakened after observing the result.
