# PMQ-002.3 — Concurrent Authority Revocation Challenge

## Status

FROZEN BEFORE EXECUTION

## Purpose

Challenge whether a represented authority-state change can become effective during the final standing-to-consequence interval and still allow a consequence to form under the now-stale execution permit.

## Frozen proposition

> Once a newer authority state has committed, a permit bound to the previous authority-state version MUST NOT subsequently form the represented protected consequence.

The proposition is deliberately about commit ordering. It does not require a revocation attempt that begins after the final standing check to retroactively invalidate a consequence whose protected formation boundary already owns the authority-state guard.

## Test method

1. Obtain an ALLOW decision and valid execution permit bound to the current authority-state version.
2. Start a represented authority revocation/state advance concurrently with consequence execution.
3. Exercise both meaningful orderings at the protected boundary:
   - revocation commits before execution acquires the final authority-state boundary;
   - execution acquires the final boundary first while revocation attempts to commit before consequence formation.
4. Assert that if revocation commits first, the stale permit is denied and no represented consequence forms.
5. Assert that if execution owns the boundary first, revocation cannot commit inside the final standing-to-formation interval; the consequence may form under the still-current state and the state change commits only afterwards.

## Failure conditions

Classify **FAIL — CONSEQUENCE FORMED AFTER COMMITTED AUTHORITY REVOCATION** if the newer authority state is demonstrably committed before the protected execution boundary resolves standing and the old permit nevertheless forms the represented consequence.

Also classify FAIL if the authority-state mutation can commit inside the represented final standing-to-formation critical section.

## Claim boundary

This is a represented in-process concurrency test using the reference authority-state guard. A PASS does not establish distributed revocation propagation, database transaction isolation, multi-node consensus, external IAM revocation, trusted messaging, or prevention on external payment rails.

The test semantics must not be weakened after observing the result.
