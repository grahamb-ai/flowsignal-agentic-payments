# PMQ-002.3 — Concurrent Authority Revocation Result

## Frozen proposition

> Once a newer authority state has committed, a permit bound to the previous authority-state version MUST NOT subsequently form the represented protected consequence.

## Result

**PASS — represented in-process authority revocation ordering enforced**

## What was exercised

Two orderings were tested without changing the frozen proposition:

1. **Revocation commits first.** A valid execution permit was issued against the current authority-state version. The authority state was then advanced before protected execution proceeded. The old permit was refused as `DENIED_AUTHORITY_STATE_STALE`; no represented consequence formed.

2. **Execution owns the final boundary first.** Execution was deliberately paused after final standing resolution but before represented consequence formation. A concurrent authority-state advance was started during that interval. The state mutation could not commit while the execution boundary held the shared authority-state guard. The represented consequence formed under the still-current state; only after the protected interval completed did the newer authority state commit.

## Classification rationale

The tested mechanism establishes a deterministic ordering on the represented in-process authority-state boundary:

- a state change committed before final protected standing makes the prior permit stale and prevents represented consequence formation;
- a state change that begins after execution has acquired the protected boundary cannot commit inside the standing-to-formation interval.

No remediation was required for PMQ-002.3; the frozen challenge passed on first execution.
