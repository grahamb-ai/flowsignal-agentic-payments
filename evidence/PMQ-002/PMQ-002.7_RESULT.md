# PMQ-002.7 — Consumed-Before-Formation Crash Result

## Frozen proposition

> If a valid execution permit has been durably consumed but the executor fails before the represented consequence forms, recovery MUST preserve an explicit recoverable state showing that the consequence did not form; the system MUST NOT silently collapse that state into an indistinguishable consumed-permit replay denial.

## Initial result

GitHub Actions run `32163123583`:

**1 failed / 49 passed**

Classification:

**FAIL — CONSUMED PERMIT LEFT WITHOUT RECOVERABLE NON-FORMATION OUTCOME**

The permit was durably consumed, the injected executor exception occurred before represented formation, and no durable outcome record existed. Recovery could establish consumption but not whether the represented consequence had formed.

## Remediation

The protected consequence executor now catches a represented executor exception raised in the post-consumption/pre-formation hook, durably records `CONSEQUENCE_NOT_FORMED` for the exact permit signature and action binding, and then re-raises the original exception.

The frozen test semantics were not weakened.

## Final classification

**PASS — represented injected post-consumption/pre-formation exception leaves recoverable non-formation outcome**

A retry remains denied as `DENIED_EXECUTION_PERMIT_REPLAY`, but that denial is no longer the only durable evidence. Recovery can distinguish the failed non-forming attempt from a successfully formed represented consequence.

## Demonstrated scope

The tested reference-harness exception path now preserves an explicit durable `CONSEQUENCE_NOT_FORMED` outcome after permit consumption and before represented consequence formation.

## Residual limitations / NOT DEMONSTRATED

This does **not** establish:

- recovery from hard process kill where exception handling cannot run;
- host/power loss durability;
- atomicity between separate permit-consumption and outcome stores;
- database HA or storage-loss recovery;
- distributed transaction semantics;
- external payment-rail reconciliation;
- external exactly-once execution or physical consequence status.

Those remain separate proof obligations.

## Strongest safe conclusion

Within the represented injected-exception boundary exercised by PMQ-002.7, the previously ambiguous consumed-before-formation state is now durably distinguishable from successful represented consequence formation.
