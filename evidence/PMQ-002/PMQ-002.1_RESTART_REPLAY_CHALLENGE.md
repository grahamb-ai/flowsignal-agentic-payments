# PMQ-002.1 — Restart Replay Challenge

**Status:** Frozen challenge

## Proposition

A Runtime Authority execution permit that has already been consumed **MUST NOT** be capable of forming a second represented consequence after process restart.

## Why this test exists

The current MVP demonstrates one-time execution-permit consumption within the lifetime of a single reference process. The current implementation explicitly identifies durable duplicate suppression across restart or multiple instances as a separate proof burden.

PMQ-002.1 deliberately tests that residual boundary rather than re-testing the already-demonstrated same-process replay control.

## Frozen test procedure

1. Produce a valid `ALLOW` outcome using the existing AP-001 scenario.
2. Pass the resulting Authority Receipt through the existing Execution Gateway and obtain a valid execution permit.
3. Form the represented consequence once using that permit.
4. Simulate loss of process-local execution-consumption state by reloading the protected consequence component.
5. Present the exact same execution permit and exact same action binding again.
6. Observe whether a second represented consequence can form.

## Pass condition

The second attempt MUST NOT return `CONSEQUENCE_FORMED`.

## Fail condition

If the same already-consumed permit returns `CONSEQUENCE_FORMED` after simulated restart, classify the proposition:

**FAIL — RESTART REPLAY FORMS SECOND REPRESENTED CONSEQUENCE**

The failure must be preserved before remediation. The proposition and test semantics must not be weakened after observing the result.

## Scope

This challenge concerns the represented FlowSignal Agentic Payments MVP execution boundary only. It does not claim to reproduce operating-system, container, database, distributed-service, payment-rail or infrastructure restart semantics.

A PASS would demonstrate only that the tested reference implementation preserves consumed-permit state across the represented restart mechanism exercised by this test.

## Residual proof burdens

Regardless of the result of PMQ-002.1, separate proof remains required for:

- durable state across real process/container/host restart;
- shared replay suppression across multiple executor instances;
- distributed atomicity and consensus;
- production database durability and failure recovery;
- external payment-rail idempotency and non-duplication.
